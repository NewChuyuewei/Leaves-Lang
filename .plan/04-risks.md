# 04. 风险登记册

## 风险等级定义

| 等级  | 含义                                     |
| ----- | ---------------------------------------- |
| 🔴 高 | 可能导致核心设计推倒重来，或项目无法交付 |
| 🟡 中 | 会显著增加工作量或延期，但有已知缓解路径 |
| 🟢 低 | 影响有限，可在迭代中逐步处理             |

---

## R-001：Region 嵌套借用检查算法复杂度超预期

- **等级**：🔴 高
- **关联**：DD-003, OQ-011
- **描述**：Region 嵌套规则的借用检查，本质上是对 Rust NLL（Non-Lexical Lifetime）借用检查器的推广。若算法设计不当，可能导致：
  - 编译时间爆炸（类似早期 Rust 借用检查器的性能问题）
  - 误报过多，损害开发体验
- **应对策略**：
  1. 先实现保守版本（宁可多报错拒绝合法代码，也不放过不安全代码）
  2. 用 `.plan/examples/` 中的真实场景逐步放宽规则
  3. 参考学术界已有方案（如 Polonius、Oxide 等生命周期模型论文）而非完全自研
- **当前状态**：监控中，未开始实现

---

## R-002：有栈协程的跨平台栈切换实现

- **等级**：🔴 高
- **关联**：DD-007, OQ-003, OQ-008
- **描述**：
  - 栈切换涉及平台相关寄存器操作，需要内联汇编或平台特定代码
  - 无 GC 场景下栈不能被安全搬移，与"可增长栈"的需求存在根本张力
  - WASM 平台目前没有成熟的有栈协程实现路径
- **应对策略**：
  1. 优先支持 x86_64 Linux + Windows，ARM64/WASM 明确延后，不计入 MVP
  2. 在 Phase 2 之前投入专门的技术预研周期，做独立原型验证（不与主干开发混合）
  3. 若原型验证证明栈管理方案不可行或代价过高，启动 RFC 重新评估 DD-007（可能退回到有限形式的 async/await，作为 Plan B）
- **当前状态**：🟡 技术预研中，**这是当前项目最大的技术不确定性**

---

## R-003：独立语言生态冷启动难度

- **等级**：🟡 中
- **描述**：新语言缺乏生态，开发者不愿意投入学习成本和迁移成本，可能导致项目长期无人问津
- **应对策略**：
  1. 优先做好 C FFI 互操作层，允许渐进式迁移（现有 C/Rust 代码可被调用）
  2. 优先打磨 1-2 个"杀手级场景"的完整体验（例如：游戏开发中的 ECS 场景，利用 Region 模型的天然优势）
  3. 尽早开源，吸引社区关注和试用反馈，而非闭门造车到"完美"再发布
- **当前状态**：待规划，非当前阶段优先级

---

## R-004：项目规模远超预期（编译器+运行时+工具链+标准库）

- **等级**：🟡 中
- **描述**：完整语言生态的工作量极大，单人或小团队可能难以在合理时间内完成全部承诺的特性
- **应对策略**：
  1. 严格遵循 Phase 划分，MVP 阶段果断砍掉 Region/并发等复杂特性
  2. 评估开源社区驱动模式的可行性（吸引贡献者分担工作量）
  3. 定期回顾 Roadmap，必要时主动削减非核心特性范围（如宏系统 OQ-004 已标记为 Deferred）
- **当前状态**：持续监控

---

## R-005：Trait 系统语法改动（内联约束 + 关联类型复用泛型）可能存在隐藏的类型推断歧义

- **等级**：🟡 中
- **关联**：DD-004, OQ-010
- **描述**：关联类型并入泛型参数语法的设计尚未经过真实复杂场景（如 `Iterator`、`From`/`Into`）验证，可能在实现阶段才发现推断算法无法处理某些组合
- **应对策略**：Phase 1 阶段必须用真实标准库 trait 用例做纸面验证，而非直接进入实现
- **当前状态**：待 Phase 1 验证

---

## R-006：region\<sync> 自动同步策略可能违反"显式优于隐式"原则

- **等级**：🟢 低
- **关联**：DD-003, OQ-002
- **描述**：若自动选择锁/无锁策略的算法对开发者不透明，可能与核心设计哲学冲突，也可能导致性能不可预测
- **应对策略**：要求编译器在选择同步策略时提供可查询的诊断信息（例如 `leafc explain` 命令展示某个 region 被编译为何种同步机制），避免黑盒
- **当前状态**：设计阶段，待 Phase 4 原型验证
