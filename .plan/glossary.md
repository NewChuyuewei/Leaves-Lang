# 术语表（Glossary）

> 所有 Leaves 语言中的新造词或有特定含义的术语，必须在此登记唯一定义。
> 格式：**术语** —— 定义（首次出现于 DD-xxx / 状态）

---

## 内存模型相关

**所有权（Ownership）** —— 每个值在任意时刻有且仅有一个所有者，所有者离开作用域时值被释放。基础语义与 Rust 一致。_（DD-001）_

**Region** —— Leaves 的统一内存边界抽象，既可以是编译器自动管理的隐式生命周期区域，也可以是开发者显式声明的 `region` 块，用于批量内存分配/释放。_（DD-003）_

**隐式 Region** —— 编译器自动推断生成的 Region，对应传统意义上的"生命周期"（lifetime），开发者通常无需感知其存在。_（DD-003）_

**显式 Region** —— 通过 `region { ... }` 语法块手动声明的内存区域，内部分配的对象共享同一生命周期边界，批量释放。_（DD-003）_

**Generational Region** —— 标记为 `region X<generational>` 的区域，允许单个对象被提前删除，通过运行时世代计数器（generation counter）检测访问是否仍然有效，返回 `Option` 而非直接解引用。_（DD-003, OQ-011 待解决：与普通引用的类型区分方式）_

**世代引用（GenRef）** —— 指向 Generational Region 内对象的引用类型，访问时需要通过 `.get()` 等方法返回 `Option`，因为对象可能已被移除。_（DD-003）_

**Region 嵌套规则** —— 内层 Region 的生命周期必须被外层 Region 完全包含（内层 ⊆ 外层），类似栈帧的嵌套规则。_（DD-003）_

**`region<sync>`** —— 显式标注允许跨线程/跨 sprout 共享的 Region，编译器自动插入必要的同步机制。_（DD-003, OQ-002/OQ-009 待解决：自动同步策略与 Send/Sync 关系）_

## 生命周期与借用相关

**借用溯源分析（Borrow Provenance Analysis）** —— 针对私有/内部函数体的数据流分析技术，通过追踪 `return` 路径确定返回引用的来源参数，从而自动推断生命周期约束，无需显式标注。_（DD-002）_

**签名自洽（Signature Self-Consistency）** —— 要求 `pub` 可见性的函数，其生命周期关系必须完全由函数签名本身确定，不依赖函数体实现，以保证 API 稳定性（修改内部实现不应改变外部契约）。_（DD-002）_

**`given` 块** —— 用于表达复杂/双向泛型约束关系的语法逃生舱，替代 Rust 中 `where` 子句处理边缘复杂场景的角色。_（DD-004, OQ-001 待解决：具体语法细节）_

## 并发相关

**Sprout** —— Leaves 中的轻量级并发任务单元，基于有栈协程实现，语义类似 Go 的 goroutine，但强调结构化生命周期管理。_（DD-007）_

**Scope** —— 通过 `grove::scope(...)` 创建的结构化并发边界。关键特性：scope 同时也是一个 Region 边界，子 sprout 对外层数据的借用受 Region 嵌套规则保护；scope 退出时自动等待所有子 sprout 完成；任一子任务 panic 会触发级联取消。_（DD-007）_

**Grove** —— Leaves 官方默认并发运行时的名称，提供 M:N 调度，是标准 `Runtime` trait 的默认实现。_（DD-007）_

**级联取消（Cascading Cancellation）** —— Scope 内任一子 sprout 发生 panic 时，自动取消该 scope 内其余未完成的兄弟任务，并向上传播错误。_（DD-007）_

**`spawn_detached`** —— 显式脱离结构化 scope 管理的任务创建方式，用于真正需要"fire and forget"的后台任务场景（如日志刷盘），命名刻意带有警示性以提醒开发者放弃了生命周期保证。_（DD-007）_

**函数彩色问题（Function Coloring Problem）** —— 指 async 函数与普通函数分属两个不兼容类型系统，无法自由互调的现象。Leaves 通过放弃 Future/Poll 状态机模型，改用有栈协程从架构上消除此问题。_（DD-007）_

## 类型系统相关

**内联约束** —— 泛型参数的 trait 约束直接书写在尖括号声明处（如 `<T: Clone + Debug>`），Leaves 取消了 Rust 风格的 `where` 子句作为常规书写方式。_（DD-004）_

**内联 impl** —— 将 trait 实现代码直接写在 `struct` 定义内部的语法形式，与独立的 `impl Trait for Type { ... }` 写法可以并存混用。_（DD-004）_

**`multi` 标注** —— 应用于关联类型参数的标注，解除默认的"每个类型只能实现一次该 trait"的唯一性限制，用于支持类似 `From<T>` 的多态实现场景。_（DD-004, OQ-006 待验证）_

**`dyn_generic`** —— 应用于泛型函数的标注，使编译器采用字典传递（动态分派）而非单态化编译，用于在性能不敏感路径上减少编译产物体积和编译时间。_（DD-006, OQ-012 待解决：与 dyn Trait 的实现关系）_

## 模块与编译相关

**目录即模块** —— Leaves 的模块边界由文件系统目录结构自动确定，无需像 Rust 那样手动书写 `mod xxx;` 声明。_（DD-005）_

**跨目录强制 DAG** —— 不同目录（模块）之间的依赖关系必须构成有向无环图，禁止循环引用；同一目录内的文件允许互相循环引用。_（DD-005）_

**查询式增量编译** —— 借鉴 Salsa 框架思想，将编译的每个阶段（类型检查、借用检查等）建模为可缓存的查询节点，实现函数级别的增量重编译颗粒度。_（DD-006）_

**单态化全局去重** —— 整个项目作为统一编译会话处理泛型实例化，避免相同泛型实例在不同模块中被重复编译。_（DD-006）_
