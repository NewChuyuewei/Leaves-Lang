# Leaves 运行时微基准

用于比较**相同编译配置**的优化前后 `leav`，不用于证明 Leaves 整体优于 Lua。

## 复现

在仓库根目录运行。下面的基线提交是本轮优化之前的主线版本，不切换当前分支：

```sh
mkdir -p .work/baseline
# 解压源代码到忽略的临时目录；不会产生额外 Git 分支。
git archive c5bd7a6cffd5fb6d2f62afc7e368a02cc8378ed2 | tar -x -C .work/baseline
make -C .work/baseline linux -j4
make clean
make linux -j4
python3 bench/compare.py .work/baseline/src/leav src/leav \
  --runs 11 --iterations 1000000
```

需要 GCC、make 和 Python 3。也可向脚本传入其他两个可执行文件。
更换构建配置时，两个版本都必须重新清理和构建；不要混用默认、严格 ISO 或 sanitizer 产物。

脚本会：

1. 各预热一次，每次采样启动新进程。
2. 交替执行前后版本，降低固定执行顺序造成的偏差。
3. 使用 Lua 的 `os.clock` 测进程 CPU 时间，报告多次运行的中位数。
4. 每个工作负载都有结果断言；错误或非零退出会中止比较。

输出的 `change` 为 `(after / before - 1) * 100%`，负数表示耗时减少，
不是相同百分比的吞吐提升。短时任务容易受环境噪声影响，应增大迭代次数并重复测量。

## 工作负载

| 名称 | 内容 |
| --- | --- |
| `construct_empty` | 无构造器实例化，并核对实例类 |
| `construct_own` | 本类构造器，初始化一个字段 |
| `construct_inherited` | 通过两条继承边查找基类构造器 |
| `construct_deep` | 32 条继承边；迭代次数为主参数的十分之一，最少一次 |
| `method_dispatch` | 预先创建实例，重复调用继承方法 |
| `static_lookup` | 重复查找和调用继承的静态方法 |
| `plain_lua` | 普通 Lua 表写入、读取与数值循环，作为对照 |

这些是包含断言开销的合成任务。计时包含任务执行期间的 GC，但不包含
Lua 进程启动和类声明；每项任务前执行完整 GC。暂未测量峰值内存、
大规模应用、编译速度或模块加载，不设置容易受噪声影响的 CI 性能阈值。

## 首轮结果（局部优化实验）

环境：Linux x86_64 / glibc 2.36，GCC 12.2.0，默认 Linux 构建，
`-O2 -std=gnu99`，相同 Lua VM 配置。11 次采样，主迭代数 1,000,000。
下表为沙箱中的一次比较，不是跨机器性能保证。

| 工作负载 | 优化前中位数 ms | 优化后中位数 ms | 耗时变化 |
| --- | ---: | ---: | ---: |
| 空类构造 | 236.222 | 199.587 | -15.5% |
| 本类构造器 | 255.511 | 243.855 | -4.6% |
| 继承构造器 | 371.002 | 301.819 | -18.6% |
| 深继承构造器 | 145.307 | 58.601 | -59.7% |
| 方法调用 | 54.385 | 55.157 | +1.4% |
| 静态查找 | 100.186 | 100.079 | -0.1% |
| 普通 Lua 循环 | 19.146 | 19.180 | +0.2% |

优化仅涉及已有 Leaves 对象运行时：

- 实例化时先创建实例，再压入并设置元表，省去一次栈复制和一次删除操作。
- 继承构造器查找复用已有的成员视图 `__index` 表链，避免逐层执行多个 C API 调用。
- 保留本类原始字段的查找优先级，不添加缓存，不改变成员更新的失效规则。

没有修改 Lua VM、字节码或 GC 算法。未涉及的任务变化不应直接归因于本轮优化。
内部 `__leaves_*` 字段和视图元表仍是保留实现细节；不支持任意修改这些结构。
